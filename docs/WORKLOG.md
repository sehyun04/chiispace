# 치이스페 누적 작업 정리

정리 기준: 2026-09-22. 최초 뼈대부터 기능 구현, 오류 수정, 검증, 배포까지 묶은 기록이다.
최초 정리는 `c8e806b`부터 `d159d0c`까지의 80개 커밋, 코드, 검증 기록과 사용자 확인을 근거로 했다.
커밋 날짜와 실제 작업·배포 날짜가 다른 경우 구분했다. 이후 9월 12일의 실제 기능 구현은 6절에 추가한다.

## 현재 어디까지 됐나

치이스페는 여러 터미널 칸에 Claude·Codex를 띄우고 작업하는 Windows 데스크톱 앱이다.
칸·탭 배치, 한글 입력, Claude 대화 복원, 칸 사이 CLI·MCP 협업이 구현되어 있다.
최근 Codex의 스크롤 유실과 칸 오종료 수정까지 배포했고, 9월 11일 사용자가 “굿 잘된다”라고 확인했다.

마지막 배포 기록은 아래 4절을 따른다. `d5dc5c9`의 스크롤·칸 종료 수정도 유지한다.
문서만 정리한 커밋과 9월 12일의 새 기능·exe 배포는 구별한다.
9월 12일에 Codex 칸별 대화 복원을 추가했다. 상세 범위와 검증은 아래 6절에 기록한다.
9월 13일에는 설치된 Codex 0.154의 호환 수정과 재배포를 7절에 추가했다.
9월 15일에는 기존 커밋 푸시를 마쳤고 현재 핸드오프를 압축했다. 기록은 8절에 있다.
이어진 요청으로 권한 프로필의 칸별 자동 복원을 수정·검증·배포했다. 기록은 9절에 있다.
9월 16일 사용자가 입력·복원 실패를 다시 신고했고, 17일에 네이티브 이어가기 전환과 백스페이스 수정을 배포했다.
현재 복원 정책과 검증은 10절을 우선한다. 1·6·7·9절의 ID 기반 복원은 당시 구현 이력이다.
9월 22일에는 continue 정책을 유지하면서 칸의 자동 이름도 저장·복원하도록 보강했다. 상세는 11절에 있다.
실모델 자연어 협업 검증까지 끝났다는 뜻은 아니다.

## 1. 기능별로 진행한 작업

### 앱 기반과 터미널 연결

- kasaterm 엔진 위에 워크스페이스 뼈대를 만들고 Tauri 2 + React + xterm.js 구조로 전환했다.
- PTY·VT 파서는 직접 새로 만들지 않고 `kasa-pty`를 사용한다. 앱은 배치·세션·에이전트 연결을 맡는다.
- PTY 원시 바이트를 웹뷰에 전달하고, 입력·리사이즈·종료를 연결했다. 청크 경계의 UTF-8도 보존한다.
- 독립 실행 파일에 웹 자산을 포함했다. `custom-protocol` 누락으로 release exe가 Vite를 찾던 문제를 수정했다.
- 빌드에 TypeScript 검사를 포함하고, 터미널 엔진과 소켓 엔진의 버전을 같은 고정 rev로 관리한다.
- 앱 이름을 `chiispace`로 정리했다. 대화 저장 경로와의 연결을 지키기 위해 실제 폴더 이름은 `kasaspace`로 유지했다.

근거: `c8e806b`, `2b1027d`, `1c12990`, `9e94a97`, `768ab25`, `ace33a9`, `4595996`, `d5c2df8`.
주요 파일: [Cargo.toml](../src-tauri/Cargo.toml), [lib.rs](../src-tauri/src/lib.rs).

### 칸·탭·작업공간

- 좌우·상하 분할, 경계선 드래그, 방향별 포커스 이동, 칸 닫기를 구현했다.
- 헤더를 끌어 칸을 서로 바꾸거나 다른 칸의 가장자리에 붙이는 이동 기능을 구현했다.
- 칸을 늘릴 때 전체 배치를 균형 있게 펴서, 마지막 칸만 계속 작아지는 문제를 해결했다.
- 탭마다 배치·폴더·셸을 분리했다. 새 탭에서는 실제 설치된 셸을 고를 수 있다.
- 기본 셸은 PowerShell 계열을 우선하고, 없는 셸을 고정 목록으로 노출하지 않도록 했다.
- 사이드바를 세션 목록 중심으로 개편하고, 탭 이동·칸 선택·이름·캐릭터·폴더 표시를 모았다.
- 폴더 선택, git 브랜치·변경 파일 수, 사이드바 접기와 빈 탭 정리를 구현했다.

초기에 만든 파일 탐색기는 이후 세션 목록으로 교체했다. 현재 파일 탐색기가 있는 것으로 세지 않는다.
Alt 조합의 칸 이동도 철회하고 드래그 방식으로 바꿨다. 과거 커밋의 모든 기능이 현재 남아 있는 것은 아니다.

근거: `4a90921`, `792eb99`, `88fac51`, `77364ea`, `7890864`, `37c7505`, `94c1e3b`, `d3cf9e6`, `72448e3`.
주요 파일: [App.tsx](../ui/App.tsx), [layout.ts](../ui/layout.ts), [Sidebar.tsx](../ui/Sidebar.tsx), [shells.rs](../src-tauri/src/shells.rs).

### 입력·스크롤·화면 표시

- OS 클립보드 복사·붙여넣기, 글자 크기 조절, 링크 열기와 10,000줄 스크롤백을 연결했다.
- 한글 조합 중 자모 누출, 중복 확정, 한 글자에서 입력이 끊기는 문제를 순차 수정했다.
- 조합 종료 이벤트를 놓친 뒤 입력이 계속 막히는 문제를 blur·키 이벤트로 풀도록 했다.
- 칸 이동 후 포커스·복사가 먹통 되는 문제를 수정했다. 입력 대상은 현재 칸 ID로 찾는다.
- 칸 DOM을 평평하게 유지해 배치 변경이 터미널 언마운트와 PTY 종료로 이어지지 않도록 했다.
- Claude 스크롤백을 유지하고, 위로 스크롤한 동안 입력 상자를 화면 아래에 보조 표시한다.
- 밝은 테마에 맞춰 텍스트 대비를 조정하고, 터미널에 최소 대비 보정을 적용했다.
- UI 폰트·터미널 폰트와 폴백을 정리하고 사이드바 글자 크기를 조정했다.

근거: `c168aed`, `6f83ef5`, `a5b9021`, `bfa5815`, `a10b6b0`, `7c9b613`, `db6df58`, `e58ad13`, `69b019a`.
주요 파일: [Term.tsx](../ui/Term.tsx), [theme.css](../ui/theme.css), [app.css](../ui/app.css).

### 세션 저장과 Claude 대화 복원

아래 ID 기반 동작은 과거 이력이다. 현재는 10절의 네이티브 continue·중복 칸 선택 목록 정책을 쓴다.

- 탭·칸 배치·폴더·셸·글자 크기·이름·캐릭터 배정과 복원 명령을 저장한다.
- 시작 직후 아직 에이전트가 잡히지 않거나 종료 중 프로세스가 사라져도 복원 정보를 바로 지우지 않도록 했다.
- 여러 칸이 같은 Claude 대화로 몰리지 않도록 칸별 세션 ID를 저장하고 복원한다.
- 복원할 새 대화는 앱에서 고유 ID를 정한다. 아직 대화 파일이 없는 ID는 새 세션으로 연다.
- ID가 불명확한 칸은 다른 칸·백그라운드·다른 창의 대화를 무작정 가져오지 않도록 후보를 제한했다.
- 저장된 대화가 백그라운드에서 실행 중이면 `attach`로 연결한다.
- 다른 창이 전경에서 붙들고 있는 대화는 ID와 명령을 유지하되 자동 실행하지 않는다.
- 복원 시 Claude가 다시 출력하지 않는 이전 대화는 마지막 40개 주고받기를 셸보다 먼저 표시한다.
- 칸 이름과 Claude 대화 이름을 연결하고, 이름이 없을 때만 마지막 요청 등으로 대신 표시한다.
- 일반 명령은 다시 쳐 놓기만 하며 빌드·배포 등을 자동 재실행하지 않는다.

이는 앞으로의 오연결을 막는 처리다. 과거에 잘못 연결된 대화의 소유권을 근거 없이 재배정하거나,
어느 대화인지 기록이 없는 모든 칸을 복구한 것은 아니다.

근거: `90237d8`, `65506c3`, `9d9ef99`, `fd6ab50`, `89688d1`, `0f228d9`, `6f8fa95`, `244af1a`, `2b2eecf`, `11831df`.
주요 파일: [session.ts](../ui/session.ts), [workspace.rs](../src-tauri/src/workspace.rs), [App.tsx](../ui/App.tsx).

### 칸 사이 기본 연결과 에이전트 협업

- 앱마다 별도 named pipe를 만들고 `chiispace-cli.exe`를 통해 칸 목록·화면 조회를 제공한다.
- 텍스트·키 전송, 분할, 포커스 이동과 닫기를 연결했다. 기본 분할은 기존 포커스를 유지한다.
- 새로 실행하는 Claude·Codex에 실행별 stdio MCP를 붙였다. 앱 내부 실행 래퍼를 사용한다.
- `context`, `delegate`, `status`, `claim`, `complete`, `cancel`, `peek` 도구를 제공한다.
- 상대 칸에 초안이 있거나 작업 중이면 위임 요청을 대기시킨다. 빈 입력창 확인 후 작업 ID만 알린다.
- 요청 본문·결과는 MCP로 교환한다. 상대 화면만 보고 작업 완료로 단정하지 않는다.
- 칸·에이전트가 재시작하거나 종료되면 이전 실행에 묶인 미완료 작업을 정리한다.
- 터미널 자동 조회 응답을 사용자 초안으로 오인하던 문제와 named pipe 연결 경합을 보완했다.
- 전역 PATH·모델·권한·사용자 설정을 덮어써서 연결하지 않는다.

기본 CLI 연결과 협업 대기열은 구현·통합 검증됐다. Claude의 네이티브 `SendMessage`·팀 인박스 연동은 아니다.
실제 모델이 자연어 요청을 이해해 다른 모델에 맡기고 결과를 회수하는 전체 흐름은 별도 실사용 검증이 남아 있다.

근거: `2b2eecf`, `421f1a7`.
주요 파일: [bridge.rs](../src-tauri/src/bridge.rs), [CLI](../src-tauri/src/bin/chiispace-cli.rs),
[collab.rs](../src-tauri/src/collab.rs), [mcp.rs](../src-tauri/src/mcp.rs), [launchers.rs](../src-tauri/src/launchers.rs), [ui/bridge.ts](../ui/bridge.ts).

### Codex 스크롤과 칸 오종료

1. 실행 래퍼에 `--no-alt-screen`을 붙였다. 이미 지정된 옵션은 중복하지 않고 resume 인자도 유지했다.
2. 이 옵션만으로 Windows 10에서 스크롤백이 생기지 않는 것을 실제 설치된 Codex에서 재현했다.
3. Microsoft ConPTY `1.24.260710001`을 검증·내장해 영역 스크롤이 화면 덮어쓰기로 유실되는 경로를 개선했다.
4. PTY 엔진과 xterm의 중복 장치·커서·색 응답이 프롬프트에 섞이지 않도록 했다.
5. 배포 후 종료 신고 때 직전 exe로 원복했다. 이후 사용자가 앱 전체가 아니라 Codex 칸만 종료됐다고 확인했다.
6. 출력 구독이 64청크 지연으로 끊겨도 앱이 이를 셸 종료로 처리하던 버그를 재현·수정했다.
7. 이제 화면 연결만 끊기면 스냅샷과 재구독으로 복구한다. 실제 EOF와 Windows 셸 프로세스 종료는 별도 확인한다.
8. 재검증 후 고정 경로에 앱·CLI를 교체했고 사용자가 정상 동작을 확인했다.

스크롤 수정과 칸 종료 수정은 모두 현재 배포본에 들어 있다. 출력 복구는 엔진에 남은 화면·스크롤백 범위다.
모든 원시 출력, Claude 프리로드 전체, 재시작 전 Codex 대화의 자동 복원까지 제공하는 것은 아니다.
신고 당시 전체 실행을 똑같이 재현한 것은 아니며, 별도로 재현한 오종료 버그 수정과 사용자 확인을 구분해 기록한다.

근거: `4ca8e5b`, `3f3e6c4`, `428c745`, `d5dc5c9`.
주요 파일: [launch.rs](../src-tauri/src/launch.rs), [conpty.rs](../src-tauri/src/conpty.rs),
[terminal-queries.ts](../ui/terminal-queries.ts), [pty_stream.rs](../src-tauri/src/pty_stream.rs).

### 테마·캐릭터와 작업 표시

- 치이카와 밝은 테마, 칸별 캐릭터 배정과 저장, 준비된 그림만 선택하는 표시 구조를 구현했다.
- 현재 기본 캐릭터 이미지 12개와 대응하는 작업 중 이미지 12개가 있다.
- 정지 이미지에서 작업 중 움직임을 만드는 스크립트와 움직임 세기 조절을 추가했다.
- 에이전트가 열려 있다는 이유만으로 작업 표시가 켜지지 않도록 사용자 제출·현재 작업 상태로 판정을 좁혔다.
- 캐릭터 테두리와 작업공간의 시각 구조를 분리하고, 세션 목록이 중심이 되도록 배치를 조정했다.

이것은 이미 진행된 작업의 기록이다. **추가 캐릭터 보강은 최후순위이며 사용자가 요청할 때만 한다.**

## 12. 9월 23일 추가: 위임 알림이 칸 이름을 덮던 문제

`ui/session.ts` 의 `paneTitle` 은 이미 "작업 이름이 아닌 것"(셸 전체 경로, `claude --continue`

## 13. 9월 23일 추가: 같은 폴더 중복 칸의 이어가기 가드 제거

사용자가 한 폴더(이 레포)에 칸을 여러 개 띄워 쓰는데, 앱을 켜면 **둘째 칸부터 이어가기 대신
대화 선택 목록**이 떴다. "continue 안 하고 resume 하는 게 왜 또 그러냐"는 신고다.

### 무엇이었나

`continuePlan` 이 `에이전트|폴더` 를 키로 중복을 세어, 같은 조합의 두 번째 칸부터
`claude --resume`(Codex 는 `--picker`)로 바꾸고 "같은 폴더의 다른 칸이 최근 대화를
이어갑니다" 안내를 붙였다. 9월 17일 네이티브 이어가기 전환(`08a0c4a`)에 들어온 것으로,
`--continue` 가 폴더 기준이라 여러 칸이 같은 대화를 잡으려다 서로 거절당하는 것을 막으려던
장치였다. 저장 자체는 멀쩡했다 — 세션 파일의 네 칸 모두 `claude --continue` 였고,
갈라친 것은 **불러올 때**다.

### 결정

사용자가 그 가드를 빼라고 했다. 여러 칸이 같은 대화를 볼 수 있다는 점은 알린 뒤에도
같은 요구였고, 실제로 그렇게 쓰고 있다고 했다. 그래서 중복 판정을 통째로 들어냈다.
`--continue` 가 폴더 기준이라는 사실은 그대로이고, 그 결과를 감당할지는 앱이 아니라
CLI 와 사용자가 정한다. `ui/App.tsx` 에서 그 판정에만 쓰이던 `roots` 계산도 같이 지웠다.

**가드를 다시 넣지 마라.** 넣으면 둘째 칸부터 선택 목록이 떠서 사용자에게는 "이어가기가
또 안 된다"가 된다. `CLAUDE.md` 의 핵심 목록에도 같은 문장을 박아 두었다.

### 검증

- `npm test` 31개 중 21개 통과·0 실패(나머지는 실제 앱 검증이라 건너뛴다), `tsc --noEmit` 통과.
- 단위 테스트 둘을 새 동작으로 뒤집었다. 같은 폴더의 네 칸이 모두 저장된 명령을 그대로 받고
  `notice` 가 없다는 것, 옵션 있는 Codex 칸도 `--picker` 로 갈리지 않는다는 것을 본다.
- `scripts/claude-continue.test.mjs` 에 실제 앱 검증을 더했다. 같은 폴더의 두 칸에
  `claude --continue` 를 저장해 앱을 띄우고, `__restore.seeds` 의 두 칸이 모두
  `claude --continue`(안내 없음)인지, 그 명령이 실제로 셸에 들어갔는지, 화면에
  `--resume`·`--session-id` 가 섞이지 않았는지 본다. 배포한 고정 경로 바이너리로 통과했다.
- `scripts/codex-resume.test.mjs` 의 중복 칸 케이스도 "둘째 칸이 첫 칸과 같은 명령을 받는다"로
  뒤집었다. 이 테스트는 실제 Codex 실행 파일을 줘야 도는 것이라 이번에 직접 돌리지는 않았다.

### 이 검증에서 배운 것

- **앱이 자기 claude 래퍼를 PATH 맨 앞에 넣는다**(`agents-<pid>`). 그래서 PATH 앞에 대역을
  두어 claude 실행을 가로채려는 시도는 통하지 않는다. 격리는 `CLAUDE_CONFIG_DIR` 로 한다.
  처음에 대역으로 짰다가 진짜 claude 가 떠서 알았다. 사용자 `~/.claude.json` 의 프로젝트
  목록은 확인 결과 오염되지 않았다 — 폴더 신뢰 확인에서 멈춰 등록까지 가지 않았다.
- **사용자 앱·claude 가 떠 있는 동안에는 "사용자 파일 해시가 그대로다"를 단언할 수 없다.**
  그 프로세스들이 정상 동작으로 자기 파일을 계속 쓴다. 실행 중이면 그 파일을 비교에서 빼고
  뺐다는 사실을 로그로 남기도록 고쳤다. 기존 실제 앱 테스트들도 같은 가정 위에 있으므로,
  앞으로 사용자 앱이 떠 있는 채 돌릴 때 같은 오탐이 날 수 있다.

## 14. 9월 23일 추가: 칸마다 제 대화로 이어가기

13절에서 중복 가드를 빼자 사용자가 겪은 것은 **모든 칸이 같은 대화로 열리는 것**이었다.
"원래 되다가 왜 안 되냐"는 신고다. 가드가 있을 때는 둘째 칸부터 선택 목록이 떴고, 빼니
전부 같은 대화가 됐다. 둘 다 원하는 것이 아니었다 — 원하는 것은 **껐다 켜도 그 칸이 보던
대화가 그대로 있는 것**이다.

### 왜 그렇게 되나

`claude --continue` 는 **폴더 기준**이다. 칸을 구별할 수단이 명령에 없다. 그래서 같은 폴더의
칸이 여럿이면 반드시 같은 대화가 된다. 이건 CLI 의 성질이지 우리 버그가 아니다.

칸마다 제 대화로 돌아오려면 대화 id 를 칸에 붙여 `--resume <id>` 하는 수밖에 없다. 그것이
9월 17일에 폐기한 방식인데, 폐기한 이유는 **id 를 추측했기** 때문이다. `~/.claude/projects/<폴더>`
의 대화 파일을 뒤져 "가장 최근 것"을 골랐고, 사용자가 이 레포에서 claude 를 켜 두고 일을
시키면 그 대화가 늘 가장 최근이라 칸이 그것을 뺏으려다 죽었다.

### 추측하지 않는 길

claude 는 뜰 때 `~/.claude/sessions/<pid>.json` 에 자기 상태를 쓴다. 확인한 실제 내용:

```json
{ "pid": 17924, "sessionId": "68e52d82-...", "cwd": "C:\Users\kshkj\desktop\sehyun\pf",
  "procStart": "134340972414295825", "name": "sionic포폴", "nameSource": "user", "status": "idle" }
```

**어느 칸이 어느 대화인지는 claude 자신이 답한다.** 고를 일이 없다. 우리가 할 일은 그 칸의
에이전트 pid 를 아는 것뿐인데, 엔진이 이미 셸의 프로세스 트리를 걸어 알고 있다
(`agent_pid_for_shell`, 표는 공유 캐시라 `ps` 가 더 돌지 않는다).

- `src-tauri/src/lib.rs` — `PaneStatus` 에 `agent_pid` 를 싣는다.
- `src-tauri/src/workspace.rs` — `claude_session_of_pid`. pid 일치·`procStart` 생존(`alive`)·
  폴더 일치(`squash`)·uuid 모양을 모두 보고, 하나라도 어긋나면 `None`. 부르는 쪽은 그때
  예전처럼 `--continue` 로 남긴다 — 나빠지지 않는다. `CLAUDE_CONFIG_DIR` 이 있으면 그 아래를 본다.
- `ui/session.ts` — `Seed.claudeSession`. **명령 문자열이 아니라 필드로 둔다.** 구형 저장분을
  정리하는 `nativeSeed` 가 문자열 속 id 를 지우기 때문이다. 필드로 두면 구형(문자열에 박힌 것)과
  지금(claude 가 스스로 답한 것)이 갈린다.
- `ui/App.tsx` — pid 가 **새로 보일 때만** 한 번 묻는다. 800ms 폴링마다 다시 물으면 같은 답에
  파일을 계속 읽는다. deps 는 정렬된 문자열로 좁혀 폴링에 effect 가 딸려 돌지 않게 했다.

### 검증

- JS 단위 33개 중 23 통과·0 실패(나머지는 실제 앱 검증이라 건너뛴다), Rust 19개 전부, `tsc --noEmit`.
- `session_of_pid_at` 단위 테스트: 이름이 다른 pid·폴더 어긋남·uuid 아닌 값·없는 pid 를 모두 거른다.
- 실제 앱·실제 claude 검증 **"칸마다 제 대화로 되살아나고 서로 섞이지 않는다"** 통과. 같은 폴더의
  두 칸에 서로 다른 합성 대화를 붙여 띄우고, 각 칸이 `claude --resume <자기 id>` 로 뜨는지,
  화면에 자기 대화만 보이고 **상대 칸의 대화가 섞이지 않는지** 본다. 사용자가 겪은 증상이
  재현되면 실패로 잡힌다. claude 는 `CLAUDE_CONFIG_DIR`·가짜 API 서버로 격리하고 모델 요청이
  없었음을 확인한다.

### 이 검증에서 걸린 것

- **격리한 claude 는 명부를 남기지 않는다**(`sessions/` 폴더만 만든다). 실사용 홈에는 멀쩡히
  쌓인다. 그래서 "명부 -> 칸 저장"은 그 파일이 놓이는 자리에 테스트가 같은 내용을 놓고 본다.
- **claude 는 실행 뒤 자기 명령줄에서 대화 id 를 지운다**(`Win32_Process.CommandLine` 에
  `--resume` 만 남는다). 그래서 칸이 둘일 때 어느 pid 가 어느 칸인지 밖에서 알 길이 없고,
  저장 검증은 매핑이 자명한 한 칸짜리로 분리했다.
- **ConPTY 가 중간에 껴서 앱 pid 아래 자손으로는 claude 가 안 잡힌다.** 테스트가 앱을 띄우기
  전후의 프로세스 차이로 고른다.

## 15. 9월 23일 추가: 터미널 대신 대화창과 실시간 표시

사용자 요청: 터미널 화면을 뜯어 띄우지 말고, kasaterm 의 아로나 모드처럼 대화로 보이게 하되
그림은 지금 쓰는 치이카와로. 답이 쓰이는 것은 cc-viewer 처럼 API 를 가로채 보여줄 것.

### 구조 — 입력은 PTY, 표시는 데이터

```
입력  : 입력바 -> pty_submit -> 칸의 PTY -> claude (지금과 같다)
지난 말: ~/.claude/projects/<폴더>/<대화 id>.jsonl -> transcript.ts -> 말풍선
쓰는 중: claude -> 앱의 루프백 프록시(proxy.rs) -> 원래 가던 API
                  └ SSE 를 옆에서 읽어 chat:live -> live.ts -> 쓰이는 말풍선
```

claude 를 헤드리스로 다시 띄우지 않는다(`docs/CHAT-DIRECTION.md` 의 처음 안). PTY 로 평소처럼
돌리므로 이어가기·권한·슬래시 명령·MCP·위임이 전부 그대로이고, 우리가 다시 만들 것이 없다.
어느 대화를 그릴지는 명부(14절)가 준 id 다 — 대화창은 고르지 않는다.

### 결정과 이유

- **대화창은 칸 위에 덮는다**(`ChatPane`). 터미널을 걷으면 PTY 가 죽고(결정 1번), 숨기면 xterm 이
  칸 수를 잃는다(결정 2번). 터미널은 아래서 제 크기로 살아 있고 머리줄 `터미널로` 단추로 오간다.
- **포커스는 `focusPane` 으로 준다.** 결정 5번의 "포커스 되돌리기"가 터미널에만 주면 대화창 아래
  숨은 xterm 이 키를 먹는다. 덮여 있으면 입력바(`window.__chats[id]`)에 준다.
- **입력 제출은 위임 쪽지와 같은 순서**: bracketed paste → 120ms → Enter(`pty_submit`). 한 덩어리로
  보내면 Enter 가 붙여넣기 안의 줄바꿈이 되어 제출되지 않는다.
- **새 대화(파일 없음)는 터미널을 보인다.** claude 의 시작 대화상자(폴더 신뢰·API 키·bypass 경고)는
  TUI 에만 있다. 대화창이 덮으면 답할 길이 없다 — 데모 중 bypass 경고로 실제로 확인했다.
  파일이 생기는 순간 대화창으로 넘어가고 포커스도 옮긴다.
- **프록시와 `ENABLE_TOOL_SEARCH=true`**. claude 는 주소가 공식 API 가 아니면 도구 미뤄 싣기를
  끈다. 요청을 들여다보니 도구 77개(MCP 43개)였고, 이걸 켜면 평소대로 14개·ToolSearch·MCP 0개,
  베타 헤더도 1st-party 그대로였다. 사용자가 이 값을 정해 두었으면 따른다.
- **구독(OAuth) 인증이 프록시를 거쳐 통한다** — 실제로 확인했다. 헤더는 넘기기만 하고 기록하지 않는다.
- **스트림의 대화는 `metadata.user_id` 의 `session_id` 로 안다.** 칸마다 주소를 따로 줄 필요가 없다.
  같은 대화 id 를 다는 서브에이전트·제목 짓기 요청은 cc-viewer 의 `isMainAgentRequest` 를 옮겨 거른다.
- **TLS 는 native-tls**. reqwest 기본 rustls 는 aws-lc-rs 라 Windows 에서 cmake·NASM 이 필요하다.
- 압축을 청하지 않는다(`accept-encoding` 제거) — 압축된 SSE 는 옆에서 못 읽는다.
- 원래 `ANTHROPIC_BASE_URL` 이 있으면 그리로 보낸다. `CHIISPACE_PROXY=0` 이면 띄우지 않는다.
- **명부를 5초마다 다시 본다.** `/clear` 로 같은 claude 가 새 대화로 넘어가면 명부가 바뀐다.
- `/model` 처럼 메뉴를 여는 슬래시 명령은 보낸 뒤 터미널로 넘어간다. 결과 없는 도구 호출이
  멈춰 있고 일하는 중이 아니면 "허락을 기다리는 것 같다" 카드를 띄운다.
- 색은 카드 바탕(`#fffdf8`)에 대고 쟀다: 내 말풍선 `#96663d`(흰 글자 4.92), 링크 `#2f7aa8`(4.62),
  오류 `#c34741`(4.81), 생각 `#7a5d99`(5.36). 하늘색 원색은 2.17 이라 링크로 못 썼다.

### 하다가 찾은 버그

1. **14절의 "칸마다 제 대화로"가 실제 앱에서 한 번도 동작하지 않았다.** Rust 가 `agent_pid` 로
   내보내고 웹뷰는 `agentPid` 를 읽어 늘 비어 있었다. 명부를 묻지 않으니 매번 `--continue` 였다.
   `#[serde(rename = "agentPid")]` 로 고쳤다. 14절의 검증은 아래 2번 때문에 돌지 못하고 있었다.
2. `claude-continue.test.mjs` 의 명부 검증이 `claudePids` 를 선언 전에 불러(TDZ) 17ms 만에 죽고 있었다.
   또 "새로 뜬 claude 는 하나"라고 가정했는데 사용자가 다른 창에서 claude 를 쓰면 둘이 된다.
   새로 생긴 pid 모두에 명부를 쓰게 바꿨다(격리 폴더라 무해하고 앱은 제 pid 것만 읽는다).
3. 명부를 한 번만 물었다. claude 가 명부를 조금 늦게 쓰면 그 칸은 영영 id 를 못 얻었다.
4. `CLAUDE_CONFIG_DIR` 을 쓰면 명부는 찾는데 대화 파일은 못 찾았다(`claude_home` 으로 맞춤).
5. 마크다운이 `agent_pid` 같은 단어 안 밑줄을 기울임으로 먹었다(GFM 규칙대로 고침).
6. 격리 claude 는 승인한 API 키를 **끝 20글자**로 기억한다. 전체만 두면 "Not logged in" 이 된다.
   기존 검증들은 모델 요청까지 가지 않아 드러나지 않았다.

### 검증

- JS 단위 79개 통과·0 실패(실제 앱 검증 13개는 기본으로 건너뜀), Rust 24개(프록시 5개 포함), `tsc`.

  - `chat-view.test.mjs` — 명부 → 대화창, 새 대화는 터미널·첫 말 뒤 대화창, 명부가 바뀌면 따라감,
    입력바 → claude 가 제출받아 원문에 적음, 포커스가 입력바로, 터미널/대화 전환.
  - `chat-live.test.mjs` — 실제 claude → 앱 프록시 → **가짜 Anthropic 서버**. 답을 붙잡아 둔 동안
    대화창에 조각이 흐르고(파일엔 아직 없음을 확인), 끝나면 파일의 답 하나로 겹침 없이 넘어간다.
    인증 헤더 도착, 압축 미요청, 중단 단추가 떴다가 사라짐까지 본다. 유료 모델은 부르지 않는다.
