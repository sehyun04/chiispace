- **복원한 칸에 지난 대화를 찍어 준다**(`244af1a`). claude 는 `--resume` 할 때 대화를 다시
  찍지 않아서 그 칸은 위로 올려다봐도 비어 있었다(9MB 대화를 되살렸을 때 스크롤백 0줄).
  이제 셸보다 먼저 마지막 40개 주고받기를 쓴다. 25번 참고.
- **글자 대비를 확보했다**(`69b019a`). 파스텔을 밝은 터미널에 그대로 쓰던 것이라 상태줄
  노랑이 대비 1.41 이었다. 색조는 두고 명도만 내렸고, claude 가 직접 보내는 트루컬러는
  `minimumContrastRatio` 로 잡는다. 26번 참고.
- **검증이 사용자 세션 파일을 못 건드리게 했다**(`CHIISPACE_STATE`). 이번 사고의 절반이
  그것이었다 — 어떤 세션이 없는 대화 id 를 사용자 파일에 써 넣고 되돌리지 않았고, 앱이
  그 값을 계속 재생산해 손으로는 빠져나올 길이 없었다. 24번 참고.
- **작업 중 판정을 사용자가 보낸 차례로 한정**(`8b8e0ba`). 병렬로 돌던 다른 세션 작업이라
  커밋만 갈라 두었다.

### 다음에 할 것

**1. `--continue` 와 "새로 생긴 대화 찾기"가 백그라운드 세션을 집는다 — 지금 실제로 밟고 있다.**

이 레포에서 claude 를 백그라운드로 돌리면(`~/.claude/daemon/roster.json` 의 `workers`) 그
대화 파일이 계속 갱신된다. 그래서 `--continue` 는 그것을 열고, 새 대화 탐색도 그것을 집는다.
2026-09-05 저녁 세션 파일에 `%26 -> claude --resume 08d21654-...` 가 붙었는데 그건 **사람이
쓰던 칸이 아니라 백그라운드 작업의 대화**였다. 12번(살아 있는 것은 `attach`)이 사고로
이어지지는 않게 막아 주지만, **애초에 안 집는 것이 맞다.** 후보: 탐색·`--continue` 대체에서
`claude_bg_sessions` 에 있는 것은 빼기.

**2. 로스터 캐릭터 — 남은 것은 그림뿐이다.** 자리·배정·지정은 2026-09-02 에 붙였고,
"작업 중이면 얼굴이 움직인다"의 판정은 2026-09-05 에 사용자가 보낸 차례로 좁혔다.
`ui/assets/faces/<slug>.png` 를 넣으면 그때부터 그 얼굴이 붙는다(vite 가 모아 준다).
그림이 없는 동안은 `header_color` 로 칠한 원이 대신한다. 넣을 그림의 묘사는
`ui/assets/faces/PROMPTS.md` 에 20명분이 있다. 아직 안 한 것은 **표정으로 반응하는 것** —
지금은 헤더 얼굴 테두리가 숨 쉬는 정도다.

**3. pane 간 에이전트 연결** — 레포의 본론이자 가장 큰 구멍. upstream 에 `kasa-socket`
(cmux 호환 소켓 서버)이 이미 있으니 `kasa-pty` 처럼 당겨 쓰면 된다.

그 밖에 창 분리 · 설정 화면 · 터미널 내 검색이 없다.

### 검증할 때

**복원을 만지면 `CHIISPACE_STATE` 를 반드시 준다.** 안 주면 꾸며 넣은 값이 사용자가 실제로
쓰는 세션 파일에 눌러앉는다 — 이번에 그걸로 하루를 잃었다. 끝나면 사용자 파일이 바이트
그대로인지 해시로 확인한다. 나머지 손잡이는 README 의 "헤드리스 검증" 절에 있다.

`CHIISPACE_PROBE` 는 **한 번만** 찍는다. 값이 시간에 따라 변하는 것(스크롤백·복원 상태)을
그것으로 보면 앱이 뜨기도 전 값을 보고 오진한다 — 실제로 "스크롤백이 0줄"이라고 잘못
읽었다. 그럴 때는 표현식 안에서 `setInterval` 로 스스로 갱신하는 오버레이를 만들어 쓴다.
