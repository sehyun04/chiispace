# 대화창 방향 — 터미널에서 메신저로

> **9월 23일 — 실제로 택한 길은 이 문서의 B(헤드리스 파이프)가 아니다.** claude 는 PTY 에서 지금처럼
> 돌리고, 지난 말은 대화 파일(jsonl)에서, 쓰이는 중인 답은 앱 안 루프백 프록시가 옆에서 읽은 SSE 로
> 그린다. 헤드리스로 다시 만들 것(이어가기·권한·슬래시 명령·codex 대화 유지)이 전부 없어졌다.
> 결정과 검증은 [작업 정리 15절](WORKLOG.md#15-9월-23일-추가-터미널-대신-대화창과-실시간-표시)에 있다.
> 아래는 그 전의 밑그림이다.

**2026-09-23 스케치. 확정이 아니다.** 사용자가 참고 소스와 스킬을 주기로 했고 그것을 보고
방향을 다시 본다. 아래는 그 전에 잡아 둔 밑그림이라 **결정 근거로 인용하지 않는다.**
다만 "값 치르고 알아낸 제약" 절만은 코드와 CLI 에서 확인한 사실이라 자료가 와도 그대로다.

여기는 **왜 그 길인가**만 적는다. 무엇을 했는지는 [작업 정리](WORKLOG.md)에 쌓는다.

## 만들려는 것

칸 하나 = 터미널이던 것을 칸 하나 = **대화방**으로 바꾼다. 왼쪽에 방 목록이 있고,
방을 누르면 말풍선이 오가고, 아래 고정된 입력바에 친다. 카톡·DM 과 같은 얼개다.
터미널 화면은 사용자에게 보이지 않는다.

## 사용자가 정한 것

1. **범위 — 완전 채팅 클라이언트.** 터미널을 안 보여준다. 헤드리스 CLI 와 JSON 으로만 주고받는다.
2. **셸 칸도 안 보이게.** 방이 없을 때 목록을 누르면 "누구에게 보낼지"(claude · codex)를
   고르는 흐름으로 방을 연다. 메신저에서 대화 상대를 고르는 느낌.
3. **ID — 추측은 금지, 선택은 허용.** 아래 "ID 정책이 바뀐 이유" 참고.
4. **세션은 앱이 든다.** 방마다 파이프 프로세스를 띄운다. CLI 데몬(`--bg`)에 얹지 않는다.

## 왜 지금은 대화창이 아닌가 — 없는 메시지 경계

claude 는 TUI 로 **화면 전체를 매번 다시 그린다.** 대체 화면을 막아 두었으므로(되돌리면
회귀하는 결정 18번) 그 리페인트가 스크롤백에 그대로 쌓인다. 위로 올려 보이는 "지난 대화"는
메시지 기록이 아니라 **다시 그린 화면 찌꺼기 더미**다.

`.pinned` 가 하는 일이 그 증거다. `tailBlock()`(`ui/Term.tsx:120`)은 버퍼 밑에서 위로 훑다가
`╭` 한 글자를 찾으면 거기부터 입력 상자로 친다. 바이트 스트림에 메시지 경계가 없어서 글자
모양에 기대는 것이고, CLI 가 상자 모양을 바꾸면 그날로 깨진다.

**카톡처럼 만든다 = 없는 경계를 만들어 내는 일**이다. 화면을 파싱해서 만드는 길(A)은
리페인트 중복 제거가 불가능에 가깝고 과거 대화를 복원할 수 없어 버렸다. CLI 를 TUI 없이
돌려 JSON 을 받으면(B) 경계가 **처음부터 데이터로** 온다.

## 전송 계층

양쪽 CLI 가 이미 헤드리스 프로토콜을 갖고 있다. 우리가 발명할 것이 없다.

| | claude | codex |
|---|---|---|
| 헤드리스 출력 | `-p --output-format stream-json --verbose` | `exec --json` |
| 실시간 입력 | `--input-format stream-json` | 미확인 (`queue` · `app-server` 후보) |
| 대화 잇기 | `--resume <id>` · `-c` | `exec resume <id>` · `--last` |
| 세션 목록 | `agents` · `~/.claude/projects/*.jsonl` | `agents` |
| 권한 | `--permission-mode bypassPermissions` | `--profile` 기존 설정 그대로 |

PTY 가 아니라 **그냥 stdin/stdout 파이프**다. claude 는 왕복 경로가 확정이고,
**codex 의 대화형 유지 방식이 유일한 미확인 구역**이다. 1단계에서 그것부터 확인한다.

## 구조 — pane 인프라는 그대로 둔다

```
지금:    pane -> Term.tsx  -> PTY        -> xterm 화면
바뀐 뒤: pane -> Chat.tsx  -> 파이프      -> JSONL -> 말풍선
```

배치 트리 · 탭 · 세션 저장 · 포커스 되돌리기는 **값을 치르고 얻은 것**이고(되돌리면 회귀하는
결정 1~8번) 대화방에도 그대로 필요하다. 평평하게 깔고 좌표만 주는 것, 안 보이는 탭을
`visibility:hidden` 으로 두는 것, 배치가 바뀔 때 포커스를 손으로 되돌리는 것은 내용물이
터미널이든 말풍선이든 똑같이 필요하다.

그래서 **`Term.tsx` 를 고치지 않고 `Chat.tsx` 를 새로 만들어 칸 종류로 가른다.**

- `ui/layout.ts` 의 leaf 는 `{ kind: "leaf"; id }` 라 내용물 종류를 모른다. 손댈 필요가 없다.
- 칸 id -> 종류(`term` · `chat`) 맵만 App 이 하나 더 들면 된다.
- 되돌릴 수 있다. 종류만 되돌리면 그 칸은 다시 터미널이다.
- `Term.tsx` 를 만지는 다른 세션과 부딪히지 않는다(지금 실제로 미커밋 작업이 올라가 있다).

## ID 정책이 바뀐 이유

메신저는 방이 **여러 개**고 목록에서 고른다. `--continue` 는 "이 폴더의 가장 최근 것 하나"라
방이 둘 이상인 순간 어느 방을 열지 지목할 수단이 없다. 우회로가 없는 논리적 필연이다.

그러나 **폐기된 규칙이 실제로 낸 사고와는 성격이 다르다.**

| 폐기된 규칙이 한 짓 | 메신저에서 하는 일 |
|---|---|
| 대화 파일을 뒤져 "이 칸은 아마 이것"이라고 추측 | CLI 가 준 목록을 보여주고 **사용자가 누른 방**을 연다 |
| `--session-id` 로 새 대화를 대신 만듦 | `--resume <id>` — 기존 대화를 열 뿐 |
| 추측이 세션 파일에 박혀 **빠져나올 길이 없었다** | 방이 눈에 보이니 틀리면 즉시 보이고 다른 방을 누르면 끝 |

결정적으로 **메신저 UI 자체가 그 사고를 구조적으로 막는다.** 예전 사고의 원인은 "칸에 몰래
ID 를 붙여 두고 켤 때마다 그걸로 연다"였는데, 방이 화면에 있으면 몰래가 성립하지 않는다.
CLAUDE.md 도 "직접 지정한 attach·기타 수동 명령은 그대로 둔다"고 원래 열어 두었다.

**그래도 금지인 것:** 앱이 대화 파일을 뒤져 칸에 ID 를 붙이는 것, `--session-id` 로 새 대화를
만드는 것, 사용자가 고르지 않은 대화를 대신 고르는 것. 이 셋은 그대로 금지다.

## 값 치르고 알아낸 제약

1. **한 대화는 한 번에 한 프로세스만 연다.** 이미 열린 대화에 `--resume` 을 걸면 claude 가
   `another Claude Code on this machine already has ...` 를 남기고 죽는다(`workspace.rs:295`의
   주석에 경위가 있다). 메신저에서는 이것이 "방을 여는 순간 앱이 그 대화를 독점한다"가 되고,
   사용자가 터미널에서 같은 대화를 열지 못하게 된다. **설계에 처음부터 넣는다** — 이미 열린
   방은 목록에서 그렇게 보여야 하고, 열려다 죽은 프로세스를 빈 방으로 두면 안 된다.
2. **권한 승인은 `bypassPermissions` 를 기본으로 둔다.** 사용자가 늘 그렇게 쓴다. 다른 모드로
   넓히려면 승인 UI 를 우리가 새로 만들어야 하므로 범위를 나눈다. 권한을 임의로 넓히지 않는
   기존 규칙은 그대로다.
3. **셸 칸을 당장 지우지 않는다.** "안 보이게"는 숨기는 것부터다. PTY 경로(`Term.tsx` · IME ·
   `shells.rs` · `powershell-render.ts`)를 먼저 지워 버리면 되돌릴 곳이 없어진다.

## 사라지는 것

메시지가 데이터로 오면 존재 이유가 없어지는 편법들이다. **다만 셸 칸이 남아 있는 동안은
같이 남는다.**

- `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN` 강제(결정 18번)
- claude 칸의 스크롤백 보존 요구 — 지난 대화를 되짚는 유일한 길이었다
- `.pinned` · `tailBlock()`(결정 22번) — 입력 상자를 베껴 칸 밑에 붙이던 것
- 휠이 화살표 키가 되는 문제와 그 차단

셋 다 **"TUI 에서 대화를 되짚으려는" 시도**였다. 방향 전환으로 정리되는 것이지 잘못 짠 것이
아니다.

## 단계

값이 큰 순서가 아니라 **모르는 것이 먼저**다.

1. **전송 계층 확인.** 방 하나, 메시지 하나, 왕복. claude 의 stream-json 입출력 형식과
   세션 id 가 어디로 오는지, codex 의 대화형 유지 방식. 여기서 codex 가 막히면 2번부터의
   설계가 달라지므로 먼저 한다.
2. **`Chat.tsx` 말풍선.** 한 방만. 도구 호출을 어떻게 보일지는 이때 정한다.
3. **방 목록.** `Sidebar.tsx` 를 방 목록으로. 지금 칸 목록을 그리는 자리다.
4. **방 만들기.** 목록을 눌렀을 때 "누구에게 보낼지" 고르는 흐름.
5. **셸 칸 숨기기.** 지우지 않고 숨긴다.

## 아직 안 정한 것

- **codex 의 대화형 유지 방식** — 1단계의 첫 과제
- 도구 호출을 말풍선에 어떻게 보일지(접기 · 요약 · 감추기)
- 앱을 껐다 켤 때 방 목록을 무엇으로 복원할지
- **방을 열었을 때 지난 대화를 무엇으로 그릴지.** `--resume` 은 컨텍스트만 되살리고 과거
  메시지를 stream-json 으로 다시 뿜지 않을 가능성이 크다(미확인). 그러면 원문
  `~/.claude/projects/<폴더>/<id>.jsonl` 을 직접 읽어야 하는데 CLAUDE.md 의 "원문
  프리로드도 하지 않는다"와 걸린다. ID 정책과 **같이** 개정해야 하는 항목이다
- 스트리밍 중 부분 렌더(`--include-partial-messages`)를 쓸지
- 위임(`chiispace_delegate`)이 메신저에서 무엇이 되는지 — 단톡방인지 전달인지
